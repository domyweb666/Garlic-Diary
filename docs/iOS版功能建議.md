# 蒜數 iOS 版：該加強、該新增、該刪掉的

先講我的判斷：這個 app 的骨架很硬，那條迴圈（白天說一句 → 睡前剝三瓣 → 週對帳 → 候選兩週後判決）不要動。下面所有建議都是在這條迴圈上加油或減重，沒有一條是叫你變成另一種 app。

## 一、該加強的（已經有，但力道不夠）

1. 記一句的速度。整個 app 成立的前提是「想到就說」。網頁版要先解鎖、找到圖示、等頁面載入、按麥克風，四步。iOS 版能做到一步：鎖定畫面小工具一點就開始收音，或 Action Button、Siri「蒜數，記一句」。這是我覺得最值錢的一件事，比任何畫面都重要。
2. 提醒要能直接動手。現在的推播點了只是開 app。加一個通知動作「剝今天」直接進剝的流程，省掉一層。對帳日的提醒文案不同，這點 iOS 版已經做了。
3. 四格的判讀。現在只擋「有的時段少於四段不判斷」，沒有的那一邊也要擋，不然 1/1 對 0/20 看起來像 100% 對 0%。另外直接把兩邊差幾個百分點印出來，讀的人不用自己算。
4. 候選的關鍵字。四格全靠關鍵字比對逐字稿，AI 挑錯一個字，整條候選就廢了。加入候選清單那一刻讓人改關鍵字（加同義詞、刪誤抓的），加入之後才鎖死。預測不能改的規矩照舊，能改的只有量尺。
5. 籃子裡的蒜要能看。現在戳它只會跳。長按一顆浮出那天：日期、三瓣、完成語。籃子就從裝飾變成翻舊帳的入口，而且不用新畫面。
6. 備份。iOS 版資料已經在 app 沙盒裡、跟著 iCloud 備份走，金鑰也進了 Keychain。再往前一步是每次剝完自動丟一份 JSON 到 iCloud Drive 的 app 資料夾，換手機不用想。

## 二、該新增的

1. App Intents。一個「記一句」的 intent，Siri、捷徑、Action Button、小工具都靠它。這是上面第一條的底層。
2. 小工具。鎖定畫面一個圓的（今天那顆蒜的狀態），主畫面一個中的（今天的蒜加「記一句」按鈕，iOS 17 的互動式小工具可以直接按）。
3. 給人讀的匯出。現在只有 JSON 備份。多一個「匯出這個月的文字」，格式就用現在餵給 AI 的那種一行一段，可以直接貼進 Notion 或丟給你自己的流程。程式裡已經有這個函式，只差一個按鈕。
4. 不用金鑰的 AI。這條最大。現在要使用者自己去 Anthropic 申請金鑰貼進來，原型可以，上架不行。兩條路：一是 iOS 26 的 Foundation Models 框架，裝置上跑、免費、資料不出手機，這個任務（四週的短句裡找三條能檢驗的模式）它應付得來；二是自己架一個小代理伺服器用你的金鑰、收訂閱。我會先走第一條，金鑰留在「進階」當備用。日記 app 的賣點之一就是資料不出門，用裝置上的模型剛好把這點講圓。
5. 差在哪的歷史。每次對帳都會留一句「記憶跟紀錄差在哪」，現在散在各週的對帳裡。把這些句子排成一條清單，三個月後你會看到自己記憶的慣性，例如老是記得比實際差。這條我比較保留，因為書說對帳不做摘要。清單只是把原句排在一起，但要不要算摘要，你自己判斷。

## 三、該刪掉的

1. 設定頁的「模型」文字欄。打錯一個字就 404，一般人不會知道要填什麼。要留就留在進階區，用選單。
2. 「複製備份文字」和「貼上備份文字」。這是繞 Safari 不能下載檔案的土法，iOS 有分享面板和檔案 app，留「匯出備份檔」「匯入備份」就夠。這次移植我先照網頁版留著，下一版砍。
3. 「試用：提早開放 AI 候選」開關。這是測試用的後門，放在使用者看得到的地方，等於跟書的建議（前三週不找模式）唱反調。移到 debug 或拿掉。
4. 情境標籤，整組。這是我最想砍、也最沒把握的一條。標籤跟「說一句」在做同一件事（給那一段加情境），又多了定義、上限五個、一季不能改的規矩，剝的時候多一排 chip 要點。AI 的關鍵字已經在逐字稿上做情境比對了。砍掉以後，剝今天剩三步，各點一下。如果你實測發現有些情境講不出口、只能點，再把它加回來。
5. 聲音。iOS 上觸覺比合成音自然，兩個都開反而吵。這次兩個都做了，閘門 3 真機測完如果覺得聲音多餘，就只留觸覺。

## 四、不要加的（守住骨架）

連續天數、每日摘要、心情表情、分享到社群、成就徽章。這些跟書的方法相反：記錄不是評價，斷掉不用補。網頁版的「今天不剝」和「斷掉那天怎麼辦」已經把這件事講清楚了，別讓新功能把它講回去。

## 五、順序

我會這樣排：App Intents 加小工具 → 關鍵字可改加四格判讀 → 砍模型欄、備份文字、提早開放 → 裝置上的 AI → 長按看那天 → 給人讀的匯出。標籤要不要砍，等你自己剝兩週再決定。
